## Résumé pour la direction

### Scenario

Dans le cadre de la migration progressive de l’environnement DevOps de Nautilus vers Azure, il était nécessaire de mettre en place une première brique d’infrastructure de calcul simple, fiable et rapidement exploitable. L’objectif principal consistait à déployer une machine virtuelle Linux standardisée afin de fournir un point d’entrée opérationnel pour les futurs usages d’administration, d’automatisation et d’hébergement d’outils techniques.

Les exigences initiales étaient les suivantes :

- déployer la ressource dans Azure avec une configuration légère et économique ;
- utiliser une distribution Linux moderne et maintenue ;
- autoriser l’administration distante sécurisée via SSH ;
- valider immédiatement la disponibilité opérationnelle de la VM.

Cette étape était importante pour réduire le risque technique de la migration, établir une base cohérente pour les prochains déploiements et confirmer la capacité de l’équipe à provisionner rapidement des ressources cloud conformes aux besoins du programme.

### Resolution

La machine virtuelle **devops-vm** a été déployée avec succès dans le groupe de ressources **kml_rg_main-7e48a826441b4826** en région **West US** avec l’image **Ubuntu 24.04 LTS**, le format **Standard_B1s** et un disque système **Standard HDD de 30 Go**.

L’accès d’administration a été sécurisé par l’ouverture contrôlée du port **SSH 22** via les règles réseau associées. La validation finale a été réalisée avec succès grâce à une connexion SSH établie vers l’adresse IP publique attribuée à la machine virtuelle.

La valeur métier délivrée est immédiate :

- mise à disposition d’une base d’infrastructure exploitable pour la migration DevOps ;
- réduction du délai de mise en service d’un serveur Linux dans Azure ;
- création d’un socle réutilisable pour les déploiements futurs et l’industrialisation par script.

> [!SUCCESS]
> Le déploiement a été validé fonctionnellement par une connexion SSH sécurisée à l’IP publique de la VM.

## Technical Implementation

### Topology

The deployed architecture is intentionally minimal to support an incremental DevOps migration while keeping costs controlled and operational access straightforward.

Deployed components:

- **Resource Group:** `kml_rg_main-7e48a826441b4826`
- **Region:** `West US`
- **Virtual Machine:** `devops-vm`
- **Operating System:** `Ubuntu 24.04 LTS`
- **VM Size:** `Standard_B1s`
- **OS Disk:** `30 GB Standard HDD`
- **Network Security:** inbound **SSH/TCP 22** allowed
- **Access Validation:** successful SSH connection to the assigned public IP

The VM was provisioned through the Azure Portal, which automatically created the supporting networking resources typically required for a standalone deployment, including:

- a virtual network
- a subnet
- a network interface
- a public IP address
- a network security group with SSH access enabled

![Azure Configuration](@/assets/images/azure-task-20260816-081649.webp)

> [!INFO]
> For a foundational lab or migration bootstrap, a single Linux VM with restricted SSH access provides a fast and practical operational starting point.

> [!WARNING]
> Exposing port 22 to the internet is acceptable for initial provisioning or lab usage, but production environments should restrict source IP ranges and preferably use Azure Bastion or a private access pattern.

### Action

The implementation was executed using the **Azure Portal**.

Provisioning steps performed:

1. Opened the Azure Portal and selected the target subscription.
2. Created or selected the resource group:
   - `kml_rg_main-7e48a826441b4826`
3. Started a new **Azure Virtual Machine** deployment.
4. Entered the VM configuration:
   - **VM name:** `devops-vm`
   - **Region:** `West US`
   - **Image:** `Ubuntu 24.04 LTS`
   - **Size:** `Standard_B1s`
5. Configured authentication for Linux administrative access.
6. Set the OS disk configuration:
   - **Disk size:** `30 GB`
   - **Disk type:** `Standard HDD`
7. Enabled inbound access for:
   - **SSH (TCP 22)**
8. Reviewed the generated networking configuration and accepted the default supporting resources.
9. Submitted the deployment and waited for Azure provisioning to complete.
10. Retrieved the assigned public IP address.
11. Validated secure remote access using SSH to the VM public endpoint `20.245.xx.xxx`.

A typical validation command is shown below.

```bash file="ssh-validation.sh"
ssh azureuser@20.245.xx.xxx
```

> [!NOTE]
> The username depends on the administrator account defined during deployment. Replace `azureuser` with the actual Linux admin username used in the portal.

> [!DANGER]
> Private SSH keys must remain only on trusted client devices and must never be stored in source repositories or shared channels.

Successful validation confirmed that:

- the VM booted correctly,
- the network path was functional,
- SSH inbound access was properly configured,
- the platform was ready for the next migration or automation steps.

## Azure CLI

```bash file="provision-azure-linux-vm.sh"
#!/usr/bin/env bash

RG="kml_rg_main-7e48a826441b4826"
LOCATION="westus"
VM_NAME="devops-vm"
IMAGE="Ubuntu2404"
SIZE="Standard_B1s"
ADMIN_USER="azureuser"
VNET_NAME="devops-vm-vnet"
SUBNET_NAME="default"
NSG_NAME="devops-vm-nsg"
PIP_NAME="devops-vm-pip"
NIC_NAME="devops-vm-nic"
OS_DISK_NAME="devops-vm-osdisk"

# Create resource group
az group create \
  --name "$RG" \
  --location "$LOCATION"

# Create NSG and allow SSH
az network nsg create \
  --resource-group "$RG" \
  --name "$NSG_NAME" \
  --location "$LOCATION"

az network nsg rule create \
  --resource-group "$RG" \
  --nsg-name "$NSG_NAME" \
  --name "Allow-SSH" \
  --priority 1000 \
  --direction Inbound \
  --access Allow \
  --protocol Tcp \
  --source-port-range "*" \
  --destination-port-range 22 \
  --source-address-prefixes "*" \
  --destination-address-prefixes "*"

# Create VNet and subnet
az network vnet create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$VNET_NAME" \
  --subnet-name "$SUBNET_NAME"

# Create public IP
az network public-ip create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$PIP_NAME" \
  --sku Basic \
  --allocation-method Static

# Create NIC
az network nic create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$NIC_NAME" \
  --vnet-name "$VNET_NAME" \
  --subnet "$SUBNET_NAME" \
  --network-security-group "$NSG_NAME" \
  --public-ip-address "$PIP_NAME"

# Create VM
az vm create \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --name "$VM_NAME" \
  --nics "$NIC_NAME" \
  --image "$IMAGE" \
  --size "$SIZE" \
  --admin-username "$ADMIN_USER" \
  --generate-ssh-keys \
  --os-disk-name "$OS_DISK_NAME" \
  --os-disk-size-gb 30 \
  --storage-sku Standard_LRS

# Open SSH if needed at VM level
az vm open-port \
  --resource-group "$RG" \
  --name "$VM_NAME" \
  --port 22 \
  --priority 1001

# Show public IP
az vm show \
  --resource-group "$RG" \
  --name "$VM_NAME" \
  --show-details \
  --query publicIps \
  --output tsv
```

## Azure PowerShell

```powershell file="provision-azure-linux-vm.ps1"
$ResourceGroupName = "kml_rg_main-7e48a826441b4826"
$Location = "westus"
$VmName = "devops-vm"
$VmSize = "Standard_B1s"
$AdminUser = "azureuser"
$VnetName = "devops-vm-vnet"
$SubnetName = "default"
$NsgName = "devops-vm-nsg"
$PipName = "devops-vm-pip"
$NicName = "devops-vm-nic"
$OsDiskName = "devops-vm-osdisk"

# Create resource group
New-AzResourceGroup `
  -Name $ResourceGroupName `
  -Location $Location

# Create NSG rule for SSH
$NsgRule = New-AzNetworkSecurityRuleConfig `
  -Name "Allow-SSH" `
  -Description "Allow SSH" `
  -Access Allow `
  -Protocol Tcp `
  -Direction Inbound `
  -Priority 1000 `
  -SourceAddressPrefix * `
  -SourcePortRange * `
  -DestinationAddressPrefix * `
  -DestinationPortRange 22

# Create NSG
$Nsg = New-AzNetworkSecurityGroup `
  -ResourceGroupName $ResourceGroupName `
  -Location $Location `
  -Name $NsgName `
  -SecurityRules $NsgRule

# Create subnet config
$SubnetConfig = New-AzVirtualNetworkSubnetConfig `
  -Name $SubnetName `
  -AddressPrefix "10.0.0.0/24"

# Create VNet
$Vnet = New-AzVirtualNetwork `
  -ResourceGroupName $ResourceGroupName `
  -Location $Location `
  -Name $VnetName `
  -AddressPrefix "10.0.0.0/16" `
  -Subnet $SubnetConfig

# Create public IP
$Pip = New-AzPublicIpAddress `
  -ResourceGroupName $ResourceGroupName `
  -Location $Location `
  -Name $PipName `
  -AllocationMethod Static `
  -Sku Basic

# Create NIC
$Nic = New-AzNetworkInterface `
  -ResourceGroupName $ResourceGroupName `
  -Location $Location `
  -Name $NicName `
  -SubnetId $Vnet.Subnets[0].Id `
  -NetworkSecurityGroupId $Nsg.Id `
  -PublicIpAddressId $Pip.Id

# Prepare credentials
$Credential = Get-Credential -UserName $AdminUser -Message "Enter the password for the Linux VM admin account"

# Create VM config
$VmConfig = New-AzVMConfig `
  -VMName $VmName `
  -VMSize $VmSize

$VmConfig = Set-AzVMOperatingSystem `
  -VM $VmConfig `
  -Linux `
  -ComputerName $VmName `
  -Credential $Credential `
  -DisablePasswordAuthentication:$false

$VmConfig = Set-AzVMSourceImage `
  -VM $VmConfig `
  -PublisherName "Canonical" `
  -Offer "ubuntu-24_04-lts" `
  -Skus "server" `
  -Version "latest"

$VmConfig = Add-AzVMNetworkInterface `
  -VM $VmConfig `
  -Id $Nic.Id

$VmConfig = Set-AzVMOSDisk `
  -VM $VmConfig `
  -Name $OsDiskName `
  -DiskSizeInGB 30 `
  -CreateOption FromImage `
  -StorageAccountType Standard_LRS

# Create VM
New-AzVM `
  -ResourceGroupName $ResourceGroupName `
  -Location $Location `
  -VM $VmConfig

# Show public IP
Get-AzPublicIpAddress `
  -ResourceGroupName $ResourceGroupName `
  -Name $PipName | Select-Object IpAddress
```
